== Введение

Документ подробно описывает API для построения LR-автоматов по заданной грамматике.
Интерактивную страницу OpenAPI спецификации можно посмотреть link:{openApiSpec}[здесь].

API является версионируемым.
Версия задается в пути запроса (во 2 сегменте).

[#grammar]
== Грамматика

Грамматика передаётся в теле запроса при вызове методов построения LR-автоматов (<<lr0>>, <<lalr1>>, <<lr1>>).

Грамматика задаётся четвёркой:

* список терминалов (_{terminals}_)
* список нетерминалов (_{nonTerminals}_)
* список правил (_{rules}_)
* аксиома (_{startSymbol}_)

[#terminals]
=== Терминалы

Терминалы передаются в поле _{terminals}_.

Это список символов, каждый из которых:

* представляет собой строку длины 1
* не должен совпадать ни с одним нетерминалом
* не должен совпадать с прочими терминалами

[#nonTerminals]
=== Нетерминалы

Нетерминалы передаются в поле _{nonTerminals}_.

Это список символов, каждый из которых:

* представляет собой строку длины 1
* не должен совпадать ни с одним терминалом
* не должен совпадать с прочими нетерминалами

[#rules]
=== Правила

Правила передаются в поле _{rules}_.

Каждое правило состоит из двух частей:

* _{rule_left}_ - нетерминал левой части (должен содержаться в списке <<nonTerminals, нетерминалов>>)
* _{rule_right}_ - строка, задающая правую часть правила

Правая часть правила представляет собой последовательность символов, где каждый символ должен находится в объединении списков <<terminals,терминалов>> и <<nonTerminals,нетерминалов>>.

Если _{rule_right}_ - пустая строка, правило считается ε-правилом.

[#startSymbol]
=== Аксиома

Аксиома передаётся в поле _{startSymbol}_.

Это нетерминал из списка нетерминалов, с которого начинается вывод.

Аксиома должна принадлежать множеству <<nonTerminals,нетерминалов>>

[#automaton]
== LR-автомат

LR-автомат возвращается в поле _{automaton}_ при вызове методов построения:

- <<lr0>>
- <<lalr1>>
- <<lr1>>

LR-автомат состоит из:

* списка <<automatonStates,состояний>> (_{automaton_states}_)
* списка <<automatonTransitions,переходов>> между состояниями (_{automaton_transitions}_)

[#automatonStates]
=== Состояния

Состояния передаются в поле _{automaton_states}_

Каждое состояние содержит:

* _{state_name}_ - уникальное имя состояния
* _{state_items}_ - список <<stateItems,LR-пунктов>>, принадлежащих состоянию

[#lrItems]
=== LR-пункты

Каждый элемент списка _{state_items}_ представляет собой LR-пункт.

LR-пункт состоит из:

* _{rule}_ -  <<rules,правила грамматики>>
* _{item_dotIndex}_ - позиции точки в правой части правила

Поле _{item_dotIndex}_ определяет положение точки в правой части правила:

* `0` - точка стоит перед первым символом правой части правила
* `length(right)` - точка стоит в конце правой части правила правила
* `0` < _{item_dotIndex}_ < `length(right)` - точка стоит в середине правой части правила на соответствующей позиции

Если правая часть правила пустая (ε-правило), допустимое значение {item_dotIndex} равно `0`.

Состав LR-пунктов зависит от типа строиящегося автомата:

* для <<lr0,LR(0)>> и <<lalr1,LALR(1)>> используются link:https://fenya2.github.io/wiki/%D0%9B%D0%9E%D0%98/LR(0)-%D0%BF%D1%83%D0%BD%D0%BA%D1%82[LR(0)-пункт]
* для <<lr1,LR(1)>> используются link:https://fenya2.github.io/wiki/%D0%9B%D0%9E%D0%98/LR(1)-%D0%BF%D1%83%D0%BD%D0%BA%D1%82[LR(1)-пункты]

В случае использования LR(1)-пунктов, добавляется поле _{item_lookAheadSymbol}_.
Значением поля является символ из списка рассматриваемых <<terminals,терминалов>> или же символ завершения строки `⊣`.

[#automatonTransitions]
=== Переходы

Переходы передаются в поле _{automaton_transitions}_.

Каждый переход содержит:

* _{transition_from}_ - имя состояния, из которого осуществляется переход (`Исходное состояние`)
* _{transition_to}_ - имя состояния, в которое осуществляется переход (`Целевое состояние`)
* _{transition_through}_ - символ перехода

Символ _{transition_through}_ принадлежит объединению списков <<terminals,терминалов>> и <<nonTerminals,нетерминалов>> исходной грамматики.

IMPORTANT: LR-автомат полностью восстанавливается последовательным применением операций из <<buildLog,лога построения>>.

[#buildLog]
== Лог построения LR-автоматов

Вместе с LR-автоматом (<<lr0>>, <<lalr1>>, <<lr1>>) в ответе возвращается лог построения автомата.

Лог представляет из себя массив операций, которые нужно произвести, чтобы построить требуемый автомат.

У каждой операции есть имя (_{operationName}_) и пояснительное сообщение (_{operationMessage}_).

=== Уровни операций

Операции различаются по уровню важности (_{operationLevel}_).
Существует 2 уровня операций:

* _{actionLevelOperation}_
* _{commentLevelOperation}_

==== {actionLevelOperation}

Операция уровня _{actionLevelOperation}_ - ключевая операция, которую необходимо выполнить для построения автомата.
Без её выполнения автомат будет построен некорректно или его дальнейшее построение окажется вовсе невозможным.

Таких операций всего 3. Вот их имена:

* _{addStateOperation}_
* _{addItemOperation}_
* _{addTransitionOperation}_

Операции уровня _{actionLevelOperation}_ также имеют дополнительные поля (помимо _{operationName}_, _{operationLevel}_, _{operationMessage}_), которые описаны <<actionLevelOperations,ниже>>.

==== {commentLevelOperation}

Операция уровня _{commentLevelOperation}_ - вспомогательная, опциональная операция, помогающая восстановить рассуждения, которые производились, чтобы выполнить очередную операцию уровня _{actionLevelOperation}_.

[#actionLevelOperations]
=== Поддерживаемые _{actionLevelOperation}_ операции

==== {addStateOperation}

Каждое состояние в автомате имеет уникальное имя.

Операция _{addStateOperation}_ добавляет новое состояние c указанным именем в строящийся LR-автомат.
В поле _{addStateOperation_stateName}_ операциии _{addStateOperation}_ находится имя добавляемого состояния.

==== {addItemOperation}

Операция _{addItemOperation}_ добавляет <<lrItems,LR-пункт>> в одно из состояний строящегося автомата.

В поле _{addItemOperation_state}_ находится имя состояния строящегося автомата, в которое добавляется LR-пункт

В поле _{addItemOperation_item}_ находится добавляемый в это состояние <<lrItems,LR-пункт>>

==== {addTransitionOperation}

Операция _{addTransitionOperation}_ добавляет переход из одного состояние строящегося LR-автомата в другое.

В поле _{addTransitionOperation_from}_ находится имя состояния LR-автомата из которого осуществляется переход

В поле _{addTransitionOperation_to}_ находится имя состояния LR-автомата в которое осуществляется переход

В поле _{addTransitionOperation_through}_ находится символ <<grammar, грамматики>> через который осуществляется переход

=== Поддерживемые _{commentLevelOperation}_ операции

* _{extendGrammarOperation}_ - расширение исходной грамматики (добавление нового стартового правила).
* _{startAddNewTransitionsOperation}_ - начало обработки очередного состояния автомата - просмотр LR-пунктов состояния и поиск возможных переходов

[#buildOptions]
== Параметры построения автомата

В запросах на построение LR-автоматов можно передать параметры, которые будут учитываться при построении

=== {optionNamesGenerationStrategy}

Задает стратегию генерации имен состояния строящегося LR-автомата.
Поддерживаются 2 стратегии. По умолчанию используется стратегия:

*{optionNamesGenerationStrategyByTransition}* - по символу перехода.

Стартовому состоянию дается имя `∇`. Имя очередного состояния, добавляемого в процессе построения формируются в формате:

[quote]
TRANSITION_SYMBOL + NUMBER

где:

* _TRANSITION_SYMBOL_ - лексическое значение символа, по которому осуществляется переход в новое состояние
* _NUMBER_ - порядковый номер состояния, присваиваемый автоматически при его добавлении в автомат. Нумерация начинается с 1 для первого добавленного состояния и увеличивается на 1 для каждого нового состояния.

IMPORTANT: используется по умолчанию

*_endToEndNumeric_* - сквозная нумерация состояний.

Стартовому состоянию дается имя `0`. Каждое последующее добавляемое в автомат состояние получает имя в виде следующего целого числа (1, 2, 3, ...).
